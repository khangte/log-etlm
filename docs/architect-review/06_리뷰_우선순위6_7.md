## 6. `_normalize_event_id_value` 축약

- `_normalize_event_id_value` 함수 전체 삭제, `import unicodedata` 삭제 확인.
- `event_id_rule_version` 필드·`_v` 세그먼트·id 접두사에서 전부 제거 확인
  (`evt_v1_<32hex>` → `evt_<32hex>`).
- `_seed_segment`는 `f"{name}:{len(text)}:{text}"`로 인라인됐고,
  **길이 프리픽스가 그대로 유지됨을 코드로 확인** — 설계 문서가 감사 제안과
  달리 유지를 권한 핵심 지점이 정확히 반영됨.
- `event_id_seed_fields` 17개 필드 순서도 변경 없음.
- 회귀 테스트 `tests/simulator/test_event_id.py`: 고정 입력 dict로 기대값
  `evt_693c26a0eef96e3f28631d18f0d5571b`를 박아 뒀다. 실제 seed 조합 로직을
  Python으로 독립 재현해 blake2b 해시를 직접 계산해봤고, 테스트 기대값과
  정확히 일치함을 확인했다(단순 육안 확인이 아니라 실제 재계산 검증).
- `sim = BaseServiceSimulator(routes=[{"weight": 1}], profile={})` 생성자
  호출은 `__slots__`에 `routes`/`profile`이 있어 유효. 이 저장소 시스템
  python에 `orjson`이 없어 실제 pytest 실행은 불가했으나(이전 리뷰에서
  짚은 것과 동일한 환경 문제), 로직 자체는 별도로 재현·검증했다.
- 9개 대상 파일 전부 `ast.parse` 구문 검사 통과.

## 7. 설정 캐시 → `lru_cache`

8개 지점 전부 확인:

- 동일 패턴 7개(`get_stream_ingest_settings`, `get_fact_stream_settings`,
  `get_clickhouse_settings`, `get_batch_timing_log_settings`,
  `get_simulator_settings`, `get_publisher_settings`,
  `get_producer_settings`) — `@lru_cache(maxsize=1)` 전환, 모듈 전역
  `_*_cache`/`global` 문 삭제 확인.
- 예외 1개 `get_queue_config()` — 선택 인자 `settings` 제거하고 무인자
  `@lru_cache(maxsize=1)`로 전환, 내부에서 `get_simulator_settings()` 호출.
  공개 함수 `build_queue_config(settings)`는 그대로 남아 임의 settings로
  큐 정책을 만드는 기능 자체는 살아있음 확인.
- 호출부 3곳 전부 무인자 `get_queue_config()`로 수정 확인:
  `task_builder.py`의 `create_simulator_tasks()`(21행 부근),
  `create_service_tasks_only()`(62행 부근), `stream_pipeline.py`의
  `run_simulator_loop()`(41행). `task_builder.py`의 `settings` 로컬 변수는
  다른 곳(`queue_size`, `loops_per_service`, `log_batch_size` 등)에서 계속
  쓰여 미사용 변수로 남지 않음.
- `log_simulator/publisher/dlq.py`, `log_simulator/producer/kafka_client.py`
  둘 다 `git diff --stat` 결과 diff 없음 — 미변경 확인. 여전히 기존
  `global _dlq_publisher` / `global _client` 패턴 그대로.
- 잔여 `_settings_cache` 등 옛 캐시 변수 grep 결과 전무.
- 9개 파일 전부 `ast.parse` 구문 검사 통과.
