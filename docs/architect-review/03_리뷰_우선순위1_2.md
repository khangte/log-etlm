## 1. pytest 전환

정적 검토만 가능했다. `uv run pytest`가 이 저장소에서 `pyproject.toml` 자체가
없어 spawn 실패하고, `.venv`/시스템 python 어디에도 pytest가 설치돼 있지
않다. 지시서가 "requirements에 pytest 없음 — 별건, 이번 범위 아님"이라 명시한
바로 그 이슈이므로 개발자 책임이 아니다. 실행 검증은 lead 쪽 환경(VM 등)에서
별도로 필요하다.

수집 테스트 개수는 코드를 읽고 수동 계산했다.

- clickhouse: parametrize 4 + url 포함 1 = **5**
- fact: dedup_keys 6 + watermark 5 + 시나리오 2개(각 assert 2개, 테스트 함수는 2개) = **13**
- timestamp: 컬럼 포함 4 + 컬럼 미포함 8 + banned 스캔 1 + DDL 포함 5 + DDL 미포함 8 = **26**
- 합계 **44** — 지시서 완료 기준과 일치.

파일별 확인:

- `test_clickhouse_settings.py`: `check()`→`assert`, 4건 parametrize + url 포함
  단건 분리. 지시대로.
- `test_fact_settings.py`: dedup_keys/watermark parametrize, 시나리오 2개는
  한 테스트 함수 안에 단언 2개씩 유지. 지시대로.
- `test_timestamp_columns.py`: `_extract_list_from_ast`/`scan_banned_patterns`
  로직 그대로 유지, 출력·집계 계층만 제거. `assert not hits, _format_hits(hits)`로
  진단 메시지 보존됨(지시서가 "가장 놓치기 쉬운 지점"이라 짚은 부분, 잘 반영됨).
  `"url" in opts` 류 포함 체크도 `== True`로 바뀌지 않고 원형 유지.
- 각 파일 헤더 주석 실행법이 `uv run pytest ...`로 갱신됨.
- 루트 `conftest.py`는 빈 파일로 확인. 기존
  `tests/simulator/test_api_simulator.py` 수집 정상 여부는 pytest 미설치로
  실행 확인 불가 — 위와 같은 환경 문제.

## 2. Spark env 자동전환 계층 삭제

- `scripts/{autoswitch,apply,current}_spark_env.sh`, `config/env/*.env` 전부
  삭제 확인.
- `docker-compose.yml`: `SPARK_ENV_PROFILE` 라인과 `./config/env` 마운트 라인만
  제거됨. 다른 숫자 값(`SPARK_STREAM_SHUFFLE_PARTITIONS` 등)은 손대지 않음 —
  지시 위반 없음.
- `README.md`: 크론 등록 블록, `config/env/{low,mid,high}.env` 안내, 유틸
  스크립트 목록의 Spark 프로파일 항목 모두 제거 확인.
- `ARCHITECTURE.md`: 410번 줄 트리 항목 갱신 확인.
- `CLAUDE.md`: diff가 있으나 `<!-- ai-setup:team:start -->` 자동 주입분이고,
  `@config/env/` 라인은 그대로 남아 있어 "이 작업에서 건드리지 말 것" 지시
  위반 아님. 개발자가 만든 변경이 아닌 것으로 판단.

## 스코프 이탈 (경미, 정리 요청)

`.gitignore` 끝에 지시서에 없는 `team/` 한 줄이 추가돼 있다. `.team/`
워크스페이스를 무시하려는 의도로 보이나, 패턴에 선행 dot이 빠져 있어
실제로는 아무것도 무시하지 못한다(`git check-ignore -v .team/reviewer` →
매치 없음, exit 1). 현재 `git status`에도 `.team/`이 여전히 untracked로
잡힌다. 이번 작업 지시 범위 밖 변경이니 되돌리거나, 남길 경우
`.team/`으로 고칠 것.
