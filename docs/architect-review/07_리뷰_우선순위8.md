# 우선순위 8번 구현 리뷰 결과 — task_builder 중복 병합

- 검토일: 2026-08-21
- 대상: docs/architect-review/06_task_builder_중복_병합.md 설계 지시분
- 결론: **승인**. 지적 사항 없음.

## task_builder.py

- `create_simulator_tasks`, `create_service_tasks_only` 두 함수가
  `create_service_tasks(simulators, base_eps, service_eps, publish_queue)`
  하나로 병합됨. 남긴 본문은 옛 `create_service_tasks_only`와 동일하고,
  옛 `create_simulator_tasks`의 루프 로직(`available_services`,
  `fallback_eps`, `loops`, `per_loop_eps`, 태스크 이름
  `service-loop-{service}-{idx}`, `run_simulator_loop`에 넘기는
  `log_batch_size`/`settings`/`queue_config`)과 글자 단위로 비교해도 차이
  없음 — 설계 문서 주장(공백·순서까지 동일)대로다.
- `Tuple` import 제거 확인(`typing`에서 `Any, Dict, List`만 남음).
- 반환 타입도 `List[asyncio.Task]`로 단순화, 큐 생성 책임이 완전히
  빠져나감.

## pipeline_builder.py

- `publish_queue`를 `assemble_pipeline()` 안에서 직접 생성
  (`maxsize=get_simulator_settings().queue_size`)한 뒤
  `create_service_tasks(..., publish_queue=publish_queue)`로 전달.
  `stats_queue`와 나란히 같은 자리에서 두 큐가 생기는 구조로 바뀜 —
  설계 문서 의도대로.
- `from .simulator.settings import get_simulator_settings` 추가,
  `create_simulator_tasks` → `create_service_tasks` import 교체 확인.

## engine.py

- `set_eps()` 내부의 함수 지역 import
  (`from .simulator.task_builder import create_service_tasks_only`)가
  모듈 상단으로 이동, `create_service_tasks`로 이름 교체됨.
- **순환참조 직접 확인**: `task_builder.py`는 `.settings`,
  `.stream_pipeline`, `..models.messages`만 import하고,
  `stream_pipeline.py`는 `.settings`, `..models.messages`,
  `.stream_helpers`만 import한다. `pipeline_builder.py`도
  `.simulator.settings`, `.simulator.task_builder`,
  `.publisher.worker_pipeline`, `.models.messages`만 import한다. 어느 쪽도
  `engine`을 참조하지 않으므로 상단 이동으로 인한 순환참조 없음 —
  설계 문서 주장과 일치.
- `set_eps()`의 `create_service_tasks(...)` 호출은 키워드 인자
  (`simulators`, `base_eps`, `service_eps`,
  `publish_queue=self._pipe.publish_queue`)로 돼 있어 인자 순서 변경과
  무관하게 정확히 매핑됨. `self._pipe.publish_queue`를 그대로 재사용해
  새 큐를 만들지 않는 기존 성질도 유지됨.

## 동작 차이 검증

- 잔여 참조 grep: `create_simulator_tasks`, `create_service_tasks_only`
  저장소 전체에서 매치 없음 — 옛 이름을 쓰는 호출부 없음.
- 태스크 생성 순서·개수·이름·`per_loop_eps` 계산·큐 `maxsize` 모두
  로직 대조로 확인, 동일.
- `maxsize`에 쓰는 `get_simulator_settings()`가 `@lru_cache(maxsize=1)`이라
  호출 위치가 `task_builder` 내부에서 `pipeline_builder` 상단으로
  옮겨져도 같은 캐시 객체를 반환 — 값 차이 없음.
- 세 파일 모두 `ast.parse` 구문 검사 통과.

참조하는 테스트 없음(grep 확인).
