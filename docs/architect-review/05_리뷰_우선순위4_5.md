## 4. 진단 스크립트 3종 → scripts/diag.sh 통합

원본 3개 스크립트(`git show HEAD:...`)와 `diag.sh`를 쿼리 단위로 전부
대조했다.

- `ch` 섹션: `clickhouse_diagnostics.sh`의 5쿼리 전부 텍스트 그대로 이전.
- `latency` 섹션: `publish_spike_diag.sh`의 segmented p95 / eps per minute /
  top publish_p95 3쿼리 전부 그대로 이전. 의도적으로 버린 sink/e2e p95,
  kafka→spark ingest p95 쿼리는 지시서·설계 문서 설명대로 segmented p95의
  부분집합이라 확인됨. 삭제 근거 타당.
- `parts` 섹션: `diag_partition_and_partlog.sh`의 spark-driver 로그 grep +
  part_log NewPart 쿼리 그대로 이전. 하드코딩됐던
  `docker exec -it clickhouse ... -u log_user --password log_pwd`,
  `database='analytics'`가 `run_query()` + 환경변수(`CLICKHOUSE_CONTAINER`,
  `CLICKHOUSE_USER`, `CLICKHOUSE_PASSWORD`, `CLICKHOUSE_DB`)로 교체됐고
  기본값이 원본과 동일해 동작 변화 없음.
- `-it` → `-i` 통일 확인 (`ch`, `parts` 두 섹션 모두 `run_query()`를 공유해
  일괄 적용됨).
- `#!/bin/bash` → `#!/usr/bin/env bash` 확인.
- `WINDOW_MIN`은 `latency` 전용 유지, `parts`의 5분 윈도우는 상수로 유지 —
  지시대로.
- `bash -n scripts/diag.sh` 문법 검사 통과.
- README.md 190-191행이 `scripts/diag.sh <ch|latency|parts|all>` 한 줄로
  교체됨 확인.
- 잔여 참조 grep: 코드/README 어디에도 옛 스크립트 3종 이름 없음. 남은
  언급은 감사·설계·지시 문서(이력 문서)뿐.

## 5. assemble_pipeline() 등 주입 파라미터 제거

- `pipeline_builder.py`: 키워드 파라미터 9개
  (`simulator_settings`, `queue_config`, `publisher_settings`, `producer`,
  `dlq_publisher`, `worker_count`, `log_batch_size`, `queue_size`,
  `loops_per_service`) 전부 삭제, import 5개
  (`SimulatorSettings`, `QueueThrottleConfig`, `PublisherSettings`,
  `DlqPublisher`, `KafkaProducerClient`) 동반 삭제 확인. `typing.Any`는
  `simulators` 타입에 쓰여 유지됨.
- `task_builder.py`: `create_simulator_tasks()`,
  `create_service_tasks_only()` 두 함수 모두 `settings`/`queue_config`
  파라미터 제거하고 함수 본문에서 직접 `get_simulator_settings()` /
  `get_queue_config()` 호출로 전환, `resolved_*` 중간 변수 소거 확인.
- `worker_pipeline.py`: `worker_count`, `settings`, `producer`,
  `dlq_publisher` 파라미터 제거, 내부에서 `get_publisher_settings()`,
  `get_client()`, **`get_dlq_publisher(producer)`**를 직접 호출하도록
  전환됨. `dlq_publisher=dlq_publisher`로 `PublisherWorker`에 계속 주입되는
  것도 확인 — **지시서가 강조한 "dlq_publisher 획득 동작은 유지" 요구사항이
  정확히 지켜졌다.** `DlqPublisher`/`KafkaProducerClient`/`PublisherSettings`
  import는 `PublisherWorker` 데이터클래스 필드 타입으로 계속 쓰여 그대로
  유지됨 — 타당.
- `log_simulator/publisher/dlq.py`(80줄)는 삭제되지 않고 그대로 존재 확인 —
  지시대로.
- 호출부: `engine.py`의 `assemble_pipeline()`(52-56행)과
  `create_service_tasks_only()`(95행) 둘 다 필수 인자만 넘겨 영향 없음 확인.
  저장소 전체에 다른 호출부 없음(grep 확인).
- 세 파일 모두 `ast.parse` 구문 검사 통과.
