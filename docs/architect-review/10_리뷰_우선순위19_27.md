## 1. `docs/e2e_pipeline_flow.md` backpressure 설명 정정

리뷰 지적을 승인한다.

문서는 제목에서 2단계 backpressure라고 선언하면서도 본문·도식·표에는 제거된
`QUEUE_LOW_WATERMARK_RATIO=0.2` 기반 빠른 생성 단계를 계속 명세한다. 현재 구현은 다음 두 단계뿐이다.

1. soft throttle: 큐 점유율 85% 이상에서 scale을 단계적으로 낮추고 70% 이하에서 복구
2. hard throttle: 큐 점유율 90% 이상에서 생성을 멈추고 75% 이하에서 재개

따라서 `docs/e2e_pipeline_flow.md:346-360`의 "3단계" 표현, 20% 빠른 생성 구간 도식,
`QUEUE_LOW_WATERMARK_RATIO` 표 행을 제거하고 나머지 두 단계의 진입·해제 임계값만 설명해야 한다.

## 2. `logs.unknown` 폴백·토픽 명세 제거

리뷰 지적을 승인한다.

`log_simulator/producer/topic.py`의 `get_topic()`은 `TOPICS[service]` 직접 조회로 바뀌어
미등록 서비스에서 `KeyError`를 발생시킨다. `logs.unknown` 폴백은 더 이상 존재하지 않고,
Kafka 초기화 대상도 아니다. 다음 잔재를 함께 정리한다.

- `ARCHITECTURE.md` Kafka 토픽 표의 `logs.unknown` 행
- `docker-compose.yml`의 주석 처리된 `logs.unknown` 생성 명령과 "service 누락 시 폴백" 설명
- `README.md` 시스템 아키텍처 및 Kafka 파티션 표의 `logs.unknown` 명세

README까지 포함하는 이유는 같은 22번 변경의 외부 동작을 설명하는 문서이기 때문이다.
두 리뷰 지적 파일만 고치면 README가 존재하지 않는 폴백 토픽을 계속 운영 명세로 제시한다.

## 검증 및 승인 조건

리뷰어가 보고한 검증 결과는 다음과 같다.

- Python 65파일 compile 통과
- 표적 smoke 통과
- Spark 테스트 31개 통과
- `docker compose config` 통과
- 전체 pytest는 `fastapi`/`orjson` 미설치로 수집 실패

위 문서 정합성 수정 후 관련 문자열을 저장소 전체에서 다시 검색해 런타임 폴백 명세가 남지 않았음을
확인해야 한다. 전체 pytest 미실행은 구현 실패가 아니라 검증 환경 의존성 누락이지만,
현재 판정에서는 문서 수정이 남아 있으므로 우선순위 19~27 묶음을 최종 승인하지 않는다.
